# 跨服跳蚤市场互通插件——需求文档

文档状态：草案 v0.2  
作者：Mochix2Milk  
日期：2026-08-18

## 1. 背景与目标

现有 SPT 服务端的玩家报价、卖家档案和成交结算均属于单个服务端实例。项目需要让两个独立 SPT 服务端 A、B 共享真实玩家报价，同时仍由各自服务端保存自己的玩家档案。

核心目标：

- 玩家登录 A 时，能看到并管理自己在 A 发布的报价，也能看到并购买 B 上其他玩家发布的报价。
- 玩家登录 B 时，能看到并管理自己在 B 发布的报价，也能看到并购买 A 上其他玩家发布的报价。
- 同一份报价在 A、B 上只有一个可售库存；不能发生双卖、重复结算或复制物品。
- 卖家物品、跳蚤税、声望和收款始终由卖家所在的原服处理；买家的付款和收货始终由买家当前所在服处理。

## 2. 范围定义

### 2.1 本期范围

- 两个受信任服务端之间的玩家报价互通。
- 单件、多件、整包报价。
- 仅支持卢布、美元、欧元三种货币报价；不支持物品交换。
- 报价发布、搜索、购买、部分成交、撤单、续期、到期、卖家结算和重启恢复。
- 原服离线、Hub 离线、网络超时和重复请求下的安全降级。
- 管理日志、健康状态、对账和手工禁用开关。

### 2.2 不在本期范围

- 同一玩家档案在 A、B 之间同步；本项目只同步跳蚤报价和成交事实。
- 商人报价、动态 AI 报价和 Fence 报价互通。
- 三个以上服务端的管理界面、跨区域高可用 Hub、多主数据库。
- 绕过 SPT 原有等级、物品禁售、报价槽位、税费、声望或库存规则。
- 客户端 BepInEx 插件。除非目标版本验证表明客户端不能接受投影报价，否则本项目应只包含服务端模组。

## 3. 术语和身份

- **原服（Origin）**：卖家发布报价和保存卖家档案的服务端。
- **买家服（Buyer Server）**：玩家发起购买时登录的服务端。
- **Hub**：共享报价与事务的唯一协调者；v1 由一个插件实例以 Hub 模式承载。
- **本地报价**：原服等于当前服务端的玩家报价。
- **远端报价**：原服不是当前服务端的玩家报价投影。
- **全局报价 ID**：Hub 分配的、符合客户端 `MongoId` 形状的 24 位十六进制 ID。
- **本地报价 ID**：原服 SPT 创建的报价 ID。
- **全局卖家 ID**：由 `serverId + profileId` 映射得到的客户端安全 ID；原始档案 ID不跨服作为唯一键使用。
- **事务 ID**：每次购买、撤单或结算的幂等键。

## 4. 前置条件与业务约束

1. A、B 目标版本固定为 SPT `4.0.13-RELEASE+2891fd4.20260302.2891fd41fd07b6150a2192ac0d24adb93eb72862`、`.NET 9.0`，并使用兼容的 EFT 数据和一致的跳蚤相关模组集合。
2. 两服必须配置不同且稳定的 `serverId`。
3. 玩家档案只允许被所属服务端写入。
4. 玩家发布时，物品按 SPT 原规则从库存移入报价托管；共享期间不得再被本地模拟买家自动买走。
5. 远端报价只是一份投影，不写入本地玩家档案，也不能触发买家服对远端卖家档案的查找。
6. Hub 是可售数量和报价状态的唯一权威来源。
7. A 的 SPT 插件实例承担 Hub；A/Hub 是已接受的单点故障。A 停止时整个跨服市场停止写操作。
8. A、B 不在同一局域网，节点通信经公网进行，必须使用 TLS 和节点鉴权。
9. 原服必须在线且成功确认托管报价后才能开始购买；原服离线时其报价可隐藏或标记不可购买，但不得成交。
10. 两服玩家档案不复制、不共用；全局身份始终使用 `serverId + profileId`。
11. 默认安全策略是 **失败关闭**：无法向 Hub 或原服确认时，禁止发布、购买、撤销或续期共享报价，但允许游戏和本地非共享功能继续运行。
12. “自己的报价”是玩家当前所在服、当前档案发布的报价；不包含另一服的独立档案报价。

## 5. 功能需求

### FR-01 节点注册与兼容性校验

- 节点启动时向 Hub 报告 `serverId`、插件版本、SPT 版本、协议版本和市场兼容哈希。
- 哈希或协议不兼容时，Hub 拒绝该节点加入共享市场，并给出可操作日志。

### FR-02 发布报价

- 原服先执行 SPT 原生校验、计税、扣税、移除库存和创建玩家报价。
- 原服档案成功保存后，通过本地 Outbox 向 Hub 发布报价快照。
- 快照至少包含原服/本地报价映射、卖家显示信息、物品树、交换条件、数量、开始/结束时间和可见性字段。
- Hub 幂等接收；同一原服和本地报价 ID 重试不得产生第二份报价。
- 发布成功后，另一服在同步延迟目标内可见该报价。

### FR-03 搜索和显示

- 本地原生报价与远端投影共同参与 SPT 原有分类、Linked Search、Required Search、价格、品质、分页和排序逻辑。
- 当前服自己的本地报价不得因远端投影再次出现而重复。
- 远端商人/AI 报价不得同步。
- 已售罄、已撤销、已到期或被隔离的报价不得返回给客户端。

### FR-04 购买远端报价

- 买家服在扣款前向 Hub 请求预占；Hub 必须确认原服在线，并让原服再次验证和锁定本地托管报价。
- 原服心跳租约失效、长连接断开或锁定确认超时，购买立即失败，不得扣款。
- 预占必须验证报价状态、剩余数量、数量规则、价格快照和事务幂等键。
- 预占成功后，买家服使用 SPT 原生库存/付款规则扣除交换物并交付物品。
- 买家档案保存成功后提交事务；保存失败则释放预占并返回失败。
- 同一事务重试只能得到同一结果，不能重复扣款或重复发货。
- 若请求同时包含本地和远端报价，v1 必须拒绝整批请求并要求客户端重试为单一来源，避免不可控的半成功。

### FR-05 原服卖家结算

- Hub 在购买提交后向原服 Outbox 生成成交事件。
- 原服消费事件时，必须按本地报价 ID 找到托管报价，并复用 SPT 的报价完成逻辑完成减量、收款邮件、声望和报价列表更新。
- 结算事件可重复投递，但同一事务只能应用一次。
- 购买开始时原服必须在线；若原服在成功锁定后意外掉线，Hub 保留已经提交的结算事件，原服恢复后幂等结算。

### FR-06 部分成交和并发

- 非整包报价允许按 SPT 原规则部分购买。
- Hub 使用条件更新保证 `available >= requested` 才能预占。
- A、B 同时抢购最后一件时只能有一个事务成功，失败方收到“报价已售罄/数量不足”。

### FR-07 撤单、续期与到期

- 撤单和续期必须先在 Hub 对报价状态执行比较并交换；存在有效购买预占时不得撤单或续期。
- Hub 确认撤单后，原服调用 SPT 原生逻辑退回剩余物品。
- 到期由 Hub 权威判定；原服确认 Hub 已终结该共享报价后调用原生到期逻辑退回剩余物品。
- 已成交数量不得因撤单或到期被退回。

### FR-08 重启恢复与对账

- Hub、原服和买家服均保存持久化事务状态。
- 持久化使用 JSON 快照与追加式 JSONL 事务日志，只依赖 .NET 9 标准库，不使用 SQLite 或其他数据库组件。
- 日志记录必须具有序号、事务 ID、前序哈希和本记录哈希；只有日志刷入磁盘后才能确认对应状态转换。
- 启动恢复必须忽略未完整写入的最后一条记录；中间记录损坏或哈希链断裂时停止共享写操作并报告错误。
- 启动后自动恢复未完成的发布、预占、提交、释放和卖家结算。
- 节点定期上报本地共享报价摘要；Hub 检测缺失、数量不一致和孤儿投影。
- 管理员可以运行只读对账；自动修复默认仅处理可证明幂等的状态。

### FR-09 配置与运维

- 配置包括节点角色、serverId、Hub 地址、共享密钥、同步周期、超时、预占 TTL、允许的支付类型和 dry-run/只读模式。
- 支持总开关、仅同步显示、禁止新交易和紧急隔离某节点。
- 日志必须包含事务 ID、全局报价 ID、原服、买家服和状态，不记录共享密钥或完整档案。

## 6. 非功能需求

- **正确性**：库存不可为负；成交、扣款、发货、卖家结算均幂等。
- **一致性**：购买采用强一致的 Hub 预占；搜索采用最终一致投影。
- **性能**：正常局域网内，95% 搜索不因同步增加超过 50 ms；购买协调目标 2 秒内完成。
- **可用性**：Hub 不可用时，本地非共享跳蚤功能是否保留由配置决定；默认只读显示缓存且禁止远端交易。
- **安全性**：节点间请求必须鉴权、防重放、限制请求体大小，并建议使用 HTTPS。
- **兼容性**：只承诺对构建时记录的精确 `SPTarkov.Server.Core` 版本兼容；跨 SPT 小版本升级需重新构建和回归。
- **可卸载性**：停用同步前必须进入排空模式，处理完预占和结算；不得直接删除仍有共享报价的插件。
- **部署依赖**：持久化不得引入第三方数据库 DLL 或原生数据库运行库。

## 7. 验收场景

1. A 玩家发布报价后，A 能看到自己的报价，B 能看到同一报价一次且可搜索。
2. B 玩家发布报价后，B 能看到自己的报价，A 能看到同一报价一次且可搜索。
3. B 买下 A 的报价后，B 买家只扣款一次并只收到一次物品；A 卖家只收到一次货款，A/B 均不再显示已售罄报价。
4. A、B 同时购买同一最后库存时恰好一方成功。
5. 同一购买请求因网络超时重试三次，最终只形成一笔成交。
6. 原服离线、心跳过期或长连接断开时，购买其报价必须失败且买家不得被扣款；已经提交的交易仍在原服恢复后完成结算。
7. 买家档案保存失败时不提交 Hub 成交，预占到期释放，卖家库存仍可售。
8. 撤单与购买并发时，只有其中一项成功，不会既退货又成交。
9. 插件重启后，未确认事务自动恢复，没有重复物品、重复货款或负库存。
10. 两服兼容哈希不同，节点被隔离，日志明确指出差异。

## 8. 已确认实施条件

- 精确目标：SPT 4.0.13 RELEASE、`.NET 9.0`；目标 DLL 和 Core XML 已放入 `ref/`。
- 网络：A、B 不在同一局域网；A 承担 Hub，接受 Hub 单点故障。
- 在线规则：原服离线不可购买其报价。
- 支付：仅卢布、美元、欧元三种货币，不开放物品交换。
- 身份：两服玩家档案不复制、不共用。
